# Full mobile app audit — 2026-10-10

The mobile app still has material functional, privacy, safety-flow, accessibility, and layout gaps. The earlier appearance report correctly did not claim full compliance. Passing the existing tests does not demonstrate that every advertised action works.

## Scope and evidence

Build-plan clarification (2026-10-10): this report describes observed gaps, including unfinished and post-MVP features; it is not a claim that all listed features were scheduled to be complete already. See the phase mapping and current implementation status in `../../../docs/PHASE16_PROGRESS.md`. Phase 16 is now in progress. Its first batch restores saved-content reads and account restoration and adds notification unread counts; the older findings remain historical evidence rather than a statement that these routes are still absent.

- Baseline inspected: local HEAD `c3c95d0` (`Fix: appearance settings now respect device accessibility`). The working tree was clean at the start. The quoted statement that nothing was committed describes an earlier state: the appearance change is now in local history. This audit made no commits or pushes.
- Concurrent changes appeared later in `bottom_navigation_bar.dart`, `chat_input_bar.dart`, `crisis_fab.dart`, `main_screen.dart`, and `ui_review_test.dart`, with separate control/crisis/regression test logs. This audit did not create those edits. The 496-test result describes the earlier snapshot, not a final green result for those later edits. The current main controls and quick-action sheet therefore need fresh verification.
- Source inventory: **268 Dart files**, including **92 files containing screens or additional screen/view classes**, **50 direct dialog/sheet/menu calls**, and **231 transient-feedback references**. These are inventory counts, not defect counts. Screen files often contain several screens.
- Reviewed the appearance report, routing, shared appearance and feedback components, feature actions, screen definitions, notification storage/repository behavior, and relevant existing test coverage. Cross-checked notification API/model behavior in the adjacent API repository where necessary.
- Fresh full regression run: **496 tests passed**. Fresh `flutter analyze`: **0 errors, 2 warnings, 9 informational notices**, exit 1. Existing notices are in tests, the vendored jailbreak package, and `tool/verify_debug_api.dart`.
- Additional diagnostic run: **108 render observations** across **27 screens/sheet bodies**, each in light/dark high contrast, 200% text, reduced motion, and 320×568 portrait / 568×320 landscape; plus **1 real Hive close/reopen observation**. **50 render observations recorded overflow findings**; the storage observation confirmed metadata loss. The **109 diagnostic tests complete successfully because they record findings rather than assert compliance**. Their green exit must not be described as 109 accessibility passes.
- Rendering probes use isolated screens, local fonts, mock platform storage, and the app's `ScreenUtil` initialization. They exercise initial states. Sheet probes measure the sheet body in a constrained viewport, rather than driving its actual modal route. They do not cover every keyboard-open, expanded, loading, error, submitted, or scrolled state.
- No Android/iOS device was connected. Device discovery found Windows, Chrome, and Edge. No physical-device screenshots, TalkBack/VoiceOver sessions, real calls/texts, account deletion, purchases, live support submissions, or production API mutations were performed. No new APK or iOS build was needed for this source-only audit. Provider dashboard and complete backend security auditing are outside this report.

This is a broad source audit with additional targeted runtime evidence, **not a completed manual walk-through of every screen, popup state, and OS notification on Android/iOS**. Remaining coverage is explicitly listed below. No report can honestly guarantee that no undiscovered mistakes remain.
